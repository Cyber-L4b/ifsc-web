HTTP na Prática: Requisição e Resposta

O que é HTTP?

HTTP significa HyperText Transfer Protocol, ou Protocolo de Transferência de Hipertexto. Ele é utilizado para permitir a comunicação entre navegadores e servidores Web.

Quando acessamos um site, o navegador utiliza o HTTP para solicitar informações ao servidor. O servidor recebe a solicitação, processa o pedido e envia uma resposta.

Por exemplo, quando digitamos o endereço de um site no navegador, ele solicita os arquivos necessários para exibir a página.

Quando essa comunicação utiliza criptografia por meio de TLS, normalmente identificamos o protocolo como HTTPS, que oferece mais segurança durante a transmissão dos dados.

Como funciona a comunicação HTTP?

Cliente

O cliente é o dispositivo ou programa que solicita informações. Um exemplo de cliente é o navegador, como Google Chrome, Firefox ou Microsoft Edge.

Servidor

O servidor é o sistema que recebe as requisições e envia respostas. Ele pode armazenar páginas HTML, imagens, arquivos e outros dados.

Requisição

A requisição é a mensagem enviada pelo cliente ao servidor. Ela informa qual recurso está sendo solicitado e qual método HTTP está sendo utilizado.

Resposta

A resposta é a mensagem enviada pelo servidor ao cliente. Ela contém um código de status e pode incluir informações, como uma página HTML ou os dados solicitados.

Etapas da comunicação

  1. O usuário acessa um endereço no navegador.
  2. O navegador envia uma requisição HTTP ao servidor.
  3. O servidor recebe e processa a requisição.
  4. O servidor envia uma resposta HTTP.
  5. O navegador interpreta a resposta e apresenta o conteúdo.

Métodos HTTP

Os métodos HTTP indicam a ação que o cliente deseja realizar sobre determinado recurso.

GET

O método GET é utilizado para solicitar informações de um servidor. Por exemplo, ao abrir uma página de notícias, o navegador pode utilizar GET para receber o conteúdo.

POST

O método POST é utilizado para enviar dados ao servidor, como informações de um formulário de cadastro.

Por exemplo, quando um usuário preenche um formulário de contato, os dados podem ser enviados ao servidor utilizando POST.

Importante: POST não é automaticamente seguro ou criptografado. Para proteger os dados durante a transmissão, deve-se utilizar HTTPS.

Exemplo de uma requisição HTTP

Abaixo temos um exemplo simplificado de uma requisição HTTP utilizando o método GET para solicitar a página inicial de um site:

GET /index.html HTTP/1.1
Host: www.exemplo.com
Accept: text/html

GET: método utilizado para solicitar o recurso.

index.html: caminho do recurso solicitado.

HTTP/1.1: versão do protocolo utilizada neste exemplo.

Host: informa o nome do servidor de destino.

Accept: informa o tipo de conteúdo que o cliente aceita receber.

Exemplo de uma resposta HTTP

Depois de receber a requisição, o servidor pode responder com uma mensagem como esta:

HTTP/1.1 200 OK
Content-Type: text/html

<html>
<head>
    <title>Meu Site</title>
</head>
<body>
    <h1>Olá, mundo!</h1>
</body>
</html>

200 OK:indica que a requisição foi processada com sucesso.

Content-Type: informa o tipo de conteúdo enviado pelo servidor.

O conteúdo HTML é o corpo da resposta. O navegador interpreta esse conteúdo e exibe a página para o usuário.

Códigos de status HTTP

Os códigos de status informam o resultado do processamento de uma requisição. Eles são divididos em categorias, como sucesso, redirecionamento, erro do cliente e erro do servidor.

200 — OK

Significa que a requisição foi processada com sucesso. Por exemplo, quando uma página é carregada normalmente.

301 — Moved Permanently

Indica que o recurso foi movido permanentemente para outro endereço. O servidor informa o novo endereço por meio do cabeçalho Location.

302 — Found

Indica um redirecionamento temporário. O recurso pode ser acessado temporariamente por outro endereço.

400 — Bad Request

Significa que o servidor não conseguiu compreender a requisição devido a um problema na mensagem enviada pelo cliente.

403 — Forbidden

Indica que o servidor entendeu a requisição, mas se recusa a permitir o acesso ao recurso.

404 — Not Found

Significa que o servidor não encontrou o recurso solicitado. Isso pode acontecer quando uma página não existe ou o endereço está incorreto.

500 — Internal Server Error

Indica que ocorreu um erro interno inesperado no servidor, impedindo que a requisição fosse concluída.

Conclusão

O HTTP é fundamental para o funcionamento da Web, pois permite que navegadores e servidores troquem informações.

Os métodos, como GET e POST, definem as ações solicitadas, enquanto os códigos de status informam o resultado da comunicação.

Compreender esses conceitos ajuda a entender como páginas, formulários e aplicações Web funcionam.
